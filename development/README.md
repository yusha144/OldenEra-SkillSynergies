# Разработка Skill Synergies

## 1. Структура

| Папка | Содержимое |
|---|---|
| source | Код мода, расчёты сочетаний и интерфейс |
| installer | Установщик и удаление |
| docs | Инструкции для игрока и демонстрационные снимки |
| development/tests | Проверки расчётов, размещения, границы IL2CPP и установщика |
| development/artifacts | Локальные результаты сборки и временные файлы, исключённые из Git |

`development/Build-Release.ps1` собирает установочный архив. `development/release-settings.json` содержит пути проектов, версию загрузчика и контрольные суммы зависимостей и игровых файлов.

## 2. Сборка и проверки

Нужны Windows, Git, Windows PowerShell 5.1, .NET SDK 8 или новее и совместимая копия игры. Установленный BepInEx 6.0.0-be.788 создаёт `BepInEx/interop` при первом запуске игры. Эти библиотеки используются для сборки мода и не хранятся в Git.

Команды выполняются из корня репозитория:

```powershell
dotnet build .\source\SkillSynergies.csproj -c Release '-p:GameRoot=<папка игры>'
dotnet run --project .\development\tests\Tests.csproj -c Release '-p:GameRoot=<папка игры>' -- '<папка игры>\HeroesOldenEra_Data\StreamingAssets\Core.zip' '.\source\bin\Release\net6.0\OldenEra.SkillSynergies.dll'
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\development\tests\Installer.Tests.ps1
```

Мод рассчитан на net6.0, проверки на net8.0. Проверки установщика работают с искусственными папками в `development/artifacts/installer-tests`. Они проверяют установку, повторный запуск, обновление, резервные копии, сохранение соседних модов и настроек, обработку ошибок и удаление.

`InteropBoundaryChecks` читает метаданные собранной DLL без загрузки игрового кода. У внедряемого `SynergyOverlay` через границу IL2CPP открыты только `Update` и `OnDestroy`. Проверка обнаруживает вспомогательные методы без `HideFromIl2Cpp`, в том числе сгенерированные компилятором.

Счётчик проверок обозначает отдельные утверждения о данных, расчётах и размещении. Он не является количеством игровых сценариев. Визуальная проверка выполняется пользователем в игре.

## 3. Установочный архив

Сначала зафиксируйте изменения в Git. Сборщик использует выбранный коммит, включая его документацию и установщик:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\development\Build-Release.ps1 -GameRoot '<папка игры>' -Revision HEAD
```

Скрипт должен совпадать с версией из выбранного коммита. Сборщик проверяет игровые файлы, собирает DLL, сверяет её версию и запускает проверки. Для расчёта состава зависимостей он использует закреплённые архивы BepInEx и Unity. Параметры `-LoaderArchive` и `-UnityLibrariesArchive` позволяют указать локальные копии с теми же SHA-256.

Результат находится в `development/artifacts/releases`. Параметр `-OutputDirectory` задаёт другую папку. Существующие файлы не перезаписываются.

| Файл | Содержимое |
|---|---|
| `OldenEra-SkillSynergies-<версия>.zip` | Install.bat, Uninstall.bat, папка _files, README, MIT и инструкции из docs |
| `.zip.sha256` | SHA-256 архива |
| `.release.json` | Версия, коммит, имя тега по версии и SHA-256 |

Внутри архива `release-manifest.json` содержит контрольные суммы поставляемых файлов. `_files/manifest.json` содержит устанавливаемые файлы и зависимости. Проверки, инструменты разработки, игровые DLL и личные настройки в установочный ZIP не входят.

Сборщик не запускает игру и не устанавливает мод. Поле `gameplayVerified = false` означает, что сборщик не выполняет игровую проверку. Отправка на GitHub, создание тега и выпуска выполняются отдельно.

## 4. Работа мода

`Plugin` сверяет SHA-256 игровых файлов. `SynergyCatalog` читает навыки, перки, условия и численные эффекты из `Core.zip`. `SynergyRules` сопоставляет текущие предложения с приобретёнными способностями героя.

`BonusPreview` учитывает базовые значения и действующие усиления. `HintPresentation` формирует эффект, условия и источники. `PanelLayout` и `HintRowLayout` рассчитывают размещение, `NativeUi` создаёт элементы внутри игрового окна. Элементы подсказок не перехватывают нажатия.

Мод не выбирает способности, не генерирует варианты и не записывает сохранения. Его состояние видимости и прокрутки существует в памяти текущего запуска.
